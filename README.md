# Tiny Snack Street / 小吃街老板 MVP

一个手机端竖屏优先的轻度经营 HTML5 小游戏原型。玩法参考海外 Poki、CrazyGames 上常见的 idle café / restaurant / shop 类循环：排队顾客、点击制作、收银赚小吃币、升级效率、雇佣助手、解锁新商品；主题与素材均为原创小吃街表达。

## 如何运行

无需构建工具，直接打开：

```bash
open index.html
```

或启动一个本地静态服务：

```bash
python3 -m http.server 5173
# 浏览器访问 http://localhost:5173
```

## 文件结构

```text
index.html   页面结构
style.css    手机端竖屏 UI、自适配与动画
game.js      玩法逻辑、本地存档、升级、离线收益
README.md    说明文档
```

## 核心玩法循环

1. 顾客进入队列并展示订单。
2. 玩家点击「开始制作」，进度条完成后点击「收银」。
3. 获得小吃币，订单数增加，队列补充新顾客。
4. 使用小吃币升级：
   - 加热台：提高制作速度。
   - 招牌套餐：提高单笔利润。
   - 小助手：自动制作，且产生离线收益。
   - 新摊位：增加队列容量，并推进更多商品解锁。
5. 3、8、15 单分别逐步解锁新商品，3-5 分钟内能体验完整成长反馈。

## 微信小游戏合规改造说明

当前版本已按中国区微信小游戏发布前原型做基础合规收敛：

- 首次进入展示试玩确认，说明适龄建议、无充值/抽奖/现金提现、仅本地存档。
- 页面底部常驻「隐私说明」「用户协议」入口。当前只使用 localStorage 保存小吃币、订单、升级、签到和最后在线时间，不提供账号注册，不采集手机号、定位、身份证、头像昵称等个人敏感信息。
- 广告能力统一标记为「激励视频广告（模拟）」，必须由用户主动触发；正式发布时应替换为微信激励视频广告 API，并仅在广告成功回调后发奖。
- 分享/邀请入口不再承诺小吃币、双倍收益等直接奖励，避免诱导分享；正式发布时应只调用微信分享面板，不强制分享。
- 好友排行仅保留入口说明，正式发布需使用微信开放数据域，不在普通业务域读取好友个人信息。

## 广告占位

当前只做模拟按钮，不接真实广告 SDK：

- 「激励广告·双倍下一单」：模拟激励视频完成后，下一单收益 x2。
- 「激励广告·快速制作」：模拟激励视频完成后，立刻完成当前制作。

## 手机适配

- 使用 `viewport-fit=cover` 和 `env(safe-area-inset-*)` 适配刘海屏安全区。
- 竖屏卡片式布局，最大宽度 480px，适配 360x640、390x844、430x932 等主流手机宽高。
- 主要按钮高度 ≥ 42px，支持 touch 操作。
- 小高度屏幕通过 media query 压缩场景高度与间距。
- 不依赖外部图片/CDN，全部使用 CSS、emoji 与本地代码。

## 本地存档

使用 `localStorage` 保存：小吃币、订单数、升级等级、双倍状态、最后在线时间。页面内提供「重置」按钮可清空存档。

## 下一步微信小游戏化建议

1. **Canvas 化或小游戏框架化**：如果要进入微信小游戏正式包，建议迁移到 Canvas/小游戏框架（如 Cocos Creator/Laya/原生 Canvas），当前 DOM 版适合作为玩法验证原型。
2. **接入微信能力**：替换假广告按钮为微信激励视频广告；接入登录、云存档、排行榜。
3. **素材升级**：把 emoji 替换为原创 2D sprite，小吃摊、顾客、商品做成统一美术风格。
4. **数值扩展**：加入每日任务、限时顾客、连击奖励、更多摊位路线，但保持轻量，避免重度数值表。
5. **矩阵复用**：当前结构可快速换皮为奶茶店、宠物咖啡、海岛摊位、便利店等题材，用同一核心循环测试不同获量素材。
